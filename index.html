Git na Prática: Comandos e Conflitos

Resumo de comandos principais

  • git init — iniciar repositório
  • git status — verificar estado do repositório
  • git add . — adicionar tudo à staging
  • git commit -m "mensagem" — salvar alteração
  • git push — enviar alterações

Branches e Fluxo de Trabalho

  • git checkout -b nome-da-branch — cria nova branch
  • git revert <hash> — reverte commit sem apagar histórico
  • git reset --hard <hash> — volta commit apagando histórico local
  • git stash — guarda alterações temporariamente
  • git stash pop — recupera alterações guardadas
  • git rebase origin/main — aplica atualizações da main
  • git push --force-with-lease — força push com segurança

Boas práticas e convenções

  • Use mensagens de commit padronizadas (feat: descricao, fix:, etc)
  • Prefira rebase ao invés de merge para manter histórico limpo
  • Siga convenção de nomes: feature/01-nome, fix/02-bug
  • Evite reset --hard em branches compartilhadas
  • Use --force-with-lease em vez de --force

Resolução de Conflito

1. Alteração local feita no código

Fizemos mudanças locais no código, iniciando o processo que pode gerar conflito.

2. Commit local com mensagem

Executamos git add . e git commit -m "gerrando o conflitinho" para registrar a mudança.

3. Usando o lápis no GitHub

Editamos o arquivo online usando o ícone de lápis do GitHub.

4. Modificação feita diretamente no GitHub

Enquanto isso, o mesmo arquivo também foi alterado diretamente no GitHub.

5. Tentativa de envio (git push)

O git push foi rejeitado pois o repositório remoto estava mais atualizado. É necessário fazer git pull.

6. Tela de resolução de conflito no VS Code

No VS Code, escolhemos entre a versão local, remota ou mesclar as duas para resolver o conflito.
