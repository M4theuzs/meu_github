Projeto Integrador — Git/GitHub

git init — Inicializa um repositório vazio

git clone <url> — Clonar repositório remoto

git status — Mostra estado da árvore de trabalho

git add <arq> — Adiciona mudanças ao estágio

git commit -m "msg" — Registrar snapshot

git push — Envia commits para o GitHub

git pull — Sincroniza e integra mudanças

git branch — Lista ou cria branches

git merge — Mescla branches

git log --oneline --graph — Histórico compacto

Resolvendo Conflitos

Passo 1 — Alteração local

No VS Code, edite o arquivo local nas linhas que depois também serão alteradas no GitHub. (Print mostra apenas a edição local.)

Passo 2 — git add e primeiro commit

Adicione as mudanças e faça o commit. (Como mostrado no print: git add . e git commit -m "mensagem".)

Passo 3 — Alteração no GitHub (remoto)

No GitHub, edite o mesmo arquivo e as mesmas linhas (o print mostra a edição direta no GitHub), provocando divergência entre local e remoto.

Passo 4 — Push rejeitado e Pull com conflito

Execute os comandos conforme aparece no print:

git push (rejeitado)
git pull (gera o conflito)

Passo 5 — Resolver o conflito no VS Code

No editor, escolha entre as opções exibidas (Accept Current / Accept Incoming / Accept Combination) até resolver o conflito, exatamente como no print.

Branches (básico)

1) Criar e trabalhar na feature

git checkout -b feature/03-branches-basico — cria a branch da feature três

git add . — adiciona mudanças

git commit -m "feat(branch):adiciona conteúdo de branches" — commit semântico

git push -u origin feature/03-branches-basico — sobe a branch

2) Manter a feature atualizada com a main

git fetch origin — busca do remoto

git rebase origin/main — reaplica seus commits sobre a main atual

Se der conflito: resolva no editor → git add . → git rebase --continue

3) (Opcional) Guardar mudanças sem commit

git stash • git stash list • git stash pop

4) Nomenclatura (kebab-case)

Ex.: feature/03-branches-basico, fix/03-ajusta-descricao, docs/03-atualiza-guia
